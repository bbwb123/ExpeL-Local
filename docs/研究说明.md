# 选题、机制与复现边界

## 为什么先选 ExpeL

组里第二项任务的关键是：选一个已有工作、冻结模型参数、复现推理侧机制、跑独立验证。
ExpeL 能直接接在 ReAct 上理解：ReAct 解决当前题，ExpeL 从过去的任务中积累可迁移经验。
原作者仓库结构清晰，分别提供 train.py、insight_extraction.py 和 eval.py。
本项目重新实现这些阶段，替换旧云端模型依赖，方便 Windows/Ollama 环境运行。
没有把同名但无关的 GitHub 仓库当作论文实现。

## 三个算法阶段

1. 经验收集：使用固定示例尝试经验集题目。完成后由评分器提供正确/错误信号；
   失败时模型阅读自身执行轨迹，写下一次尝试计划，再在重置后的环境重试。
   成功与失败都保存；不会把标准答案传给模型要求照抄。
2. 提炼规则：一条路径比较同一道题的失败/成功轨迹；另一条路径观察一组成功轨迹的共同做法。
   模型提出新增、修改、赞成、反对规则的操作，程序负责合法性检查、计分和保存。
3. 独立验证：冻结规则库和案例池，对未用于收集经验的题目检索相似成功案例，
   与经验规则一起提供给模型。每题只进行一次解题尝试；不依据验证分数更新规则。

“训练任务”在这里表示用于积累经验的任务，不表示执行梯度下降。
代码不修改权重；外部记忆和提示上下文发生变化。

## 和论文/作者实现的逐项对应

| 项目 | 原论文/作者实现 | 本项目 |
|---|---|---|
| 经验采集 | ReAct + 失败反思重试 | 保留；默认 2 次额外重试，可设置 3 |
| 两类提炼证据 | 同题失败/成功对比；多题成功批次 | 保留并记录各类批次数量 |
| 规则重要性 | ADD 初始 2；赞成/修改 +1；反对 -1；零分删除 | 保留，按票数排序；容量硬截断是简化 |
| 规则操作格式 | 论文 UPVOTE/DOWNVOTE；仓库 AGREE/REMOVE 等文本 | JSON 格式；兼容两套操作名 |
| 经验检索 | all-mpnet-base-v2 + Faiss kNN | 可选同名嵌入模型、直接向量排序；默认 BM25 |
| 解题/提炼模型 | GPT-3.5/GPT-4 系列 | 同一个冻结的 Qwen3.5-9B |
| 验证尝试次数 | 主要实验每任务单次尝试 | 保留 |
| 环境 | Wikipedia Docstore 搜索 | 默认固定百科段落库；可选 MediaWiki |
| 初始示例 | 论文示例，HotpotQA 上最多 6 条 | 附作者 6 条原始示例；默认使用 2 条 |
| 划分 | 四折验证 | 固定随机种子四折划分接口；默认仅第 0 折少量任务 |
| 指标 | HotpotQA 答案完全匹配成功率 | 答案 EM、F1、步数、耗时、token、格式错误 |

因此目前准确名称是“ExpeL 推理侧核心机制的本地适配复现”，不能称为已经复现原论文分数。
尚未实现支持事实/联合指标、跨域迁移实验、原模型组合或论文全部环境。
模型量化、中文机器环境、不同检索器、上下文窗口和搜索工具都会影响结果。

## 四组实验怎么看

- 普通 ReAct vs 只加规则：查看规则本身的影响。
- 普通 ReAct vs 只检索案例：查看检索示例的影响。
- 完整 ExpeL vs 两个单组件：查看两类经验是否互补。
- 同时统计前期积累经验和提炼规则的额外成本，不能只报告验证阶段省了多少步。

第一轮的 8/4 题配置用于排错，不做统计显著性结论。
正式比较先固定任务划分、超参数、模型摘要；不要观察验证结果后反复改提示词并仍称同一集合为最终测试。
可增加独立测试集和不同种子。无记忆组更好也应如实报告，再分析错误规则或检索干扰。

## 四折运行（确认单折正常后再做）

```powershell
python tools/run_folds.py --model qwen3.5:9b --out runs/fourfold --retriever bm25 --environment local
```

这会对 100 题样本按四折分别收集经验和验证，计算四折均值/标准误，调用量明显大于入门实验。
仍是固定语料库上的 Qwen 改编实验；换成 `--environment wikipedia --retriever mpnet` 更接近原检索设置，
但模型、提示格式、部分预算仍不同。运行前安装 requirements-semantic.txt，保证 Wikipedia 可访问。
这个脚本默认 6 条示例、3 次额外重试、8 条成功轨迹一批、32768 上下文；内存需求比入门配置更高。

## 下一次组会怎么解释

当前可说：选定了 ExpeL，读了论文和作者实现，已完成 Ollama 本地适配，以及经验收集、
规则更新、案例检索和四组对照的代码；离线测试通过。用户侧已跑通 Qwen3.5-9B 小样本流程，但四题试跑未显示 ExpeL 相对 ReAct 的收益，不能视作论文效果复现。

本地成功运行后，用实际生成的报告补充“用了什么模型、多少题、哪种环境、成功率和耗时”。
如果老师问冻结参数如何学习：通过改外部经验规则和检索到的案例改变模型输入，而不是改权重。
如果问和一次反思有什么不同：一次反思主要帮助重做当前题；ExpeL 还从多道历史题提炼规律，供新题使用。
